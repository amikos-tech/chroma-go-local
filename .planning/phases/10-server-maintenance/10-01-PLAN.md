- Single static method with this exact signature:
```java
public static <R> MaintenanceResult<R, ServerSession> execute(
        String configYaml,
        Runnable closeServerAction,
        Function<String, EmbeddedSession> startEmbeddedAction,
        Function<String, ServerSession> startServerAction,
        Function<EmbeddedSession, R> operation)
```
- Implementation follows Go's `runRebuild` (rebuild.go:184-233) error matrix exactly:

Step 1: `closeServerAction.run()` — stop+free the current server handle.

Step 2: Start temporary embedded session via `startEmbeddedAction.apply(configYaml)`. If this fails (`startErr`):
  - Try restart server: `startServerAction.apply(configYaml)`
  - If restart succeeds: throw `ChromaException` wrapping `startErr` with message "failed to start temporary embedded runtime for maintenance"
  - If restart also fails (`restartErr`): throw `ChromaException` with message "failed to start temporary embedded runtime for maintenance: {startErr}; restart failed: {restartErr}; server remains stopped" with `startErr` as cause and `restartErr` as suppressed

Step 3: Run operation: `R result = operation.apply(embedded)`. Catch RuntimeException as `opError`.

Step 4: Close embedded: `embedded.close()`. Catch RuntimeException as `closeError`.

Step 5: Restart server. Try `ServerSession newSession = startServerAction.apply(configYaml)`. Catch RuntimeException as `restartError`.

Step 6: Error matrix (matches Go switch at rebuild.go:214-232):
- `opError != null`:
  - If `closeError != null`: add closeError as suppressed to opError
  - If `restartError != null`: throw ChromaException with "{opError.message}; restart failed: {restartError.message}; server remains stopped", cause=opError, suppressed=restartError
  - Else: throw opError
- `closeError != null`:
  - If `restartError != null`: return `new MaintenanceResult<>(result, null, new ChromaException("close embedded failed: {closeError}; restart failed: {restartError}; server remains stopped"))` — per D-03, result is preserved
  - Else: return `new MaintenanceResult<>(result, newSession, null)` but throw closeError wrapped in ChromaException "maintenance completed but failed to close temporary embedded runtime"
  - Actually, re-examining Go: closeErr with no restartErr returns (result, closeErr). So: throw ChromaException wrapping closeError with result lost. But D-03 says "successful op result is never lost". Resolution: when closeError is non-null but restart succeeds, throw ChromaException wrapping closeError. When closeError is non-null and restart fails, return MaintenanceResult(result, null, combined-error). This matches Go's pattern of returning (result, error) for partial failures.
  - SIMPLIFIED approach matching D-03: if opError is null (op succeeded), always return MaintenanceResult with result. If restartError is non-null, put it in restartError field. If only closeError, wrap in restartError field too. This way the result is NEVER lost.
- `restartError != null` (no opError, no closeError): return `new MaintenanceResult<>(result, null, restartError)` — per D-03
- All null: return `new MaintenanceResult<>(result, newSession, null)` — happy path

Imports: `java.util.Objects`, `java.util.function.Function`
