**Section 2: Behavioral smoke tests**

Per D-03, create ~9-10 tests: Init, Version, NewServer, StartEmbedded, DefaultConfigs, plus one each for backup, rebuild, compaction, WAL prune option builders. Per D-05, do NOT smoke-test individual With* functions -- the compile gate covers existence, internal tests cover behavior.

Each behavioral test calls `chroma.Init("")` first (CHROMA_LIB_PATH is set by Makefile). Use `require` from testify for assertions. Call Init per-test (matching internal test patterns, per research open question 2).

The tests:

1. `TestInit` -- calls `chroma.Init("")`, asserts no error
2. `TestVersion` -- calls Init then `chroma.Version()`, asserts non-empty string
3. `TestVersionWithError` -- calls Init then `chroma.VersionWithError()`, asserts no error and non-empty string
4. `TestDefaultServerConfig` -- calls Init then `chroma.DefaultServerConfig()`, asserts non-nil and port > 0
5. `TestNewServer` -- calls Init then `chroma.NewServer(chroma.WithPort(9999))`, asserts no error and non-nil server. Call `server.Stop()` in cleanup.
6. `TestDefaultEmbeddedConfig` -- calls Init then `chroma.DefaultEmbeddedConfig()`, asserts non-nil
7. `TestBackupOptionBuilders` -- calls `chroma.WithDestination("/tmp/test")`, `chroma.WithIncludeMetadata()`, `chroma.WithLeaveStopped()`, `chroma.WithLeaveClosed()` and asserts each returns non-nil
8. `TestRebuildOptionBuilders` -- calls `chroma.WithRebuildTenantID("t")`, `chroma.WithRebuildDatabaseName("d")`, `chroma.WithRebuildPrecheck()`, `chroma.WithRebuildKeepBackup(true)` and asserts each returns non-nil
9. `TestWALPruneOptionBuilders` -- calls `chroma.WithWALPruneTenantID("t")`, `chroma.WithWALPruneDatabaseName("d")`, `chroma.WithWALPruneDryRun()`, `chroma.WithWALPruneVacuum()`, `chroma.WithWALPruneMaxAge(time.Hour)`, `chroma.WithWALPruneMaxBytes(1024)`, `chroma.WithWALPruneWatermark(2048, 1024)` and asserts each returns non-nil

Note: Tests 7-9 (option builders) do NOT need Init -- they just construct option values, which are pure Go code with no FFI dependency.

Regarding `TestNewServer`: after creating the server, call `defer server.Stop()` for cleanup. This test validates the facade's NewServer wrapper correctly delegates to the internal implementation.

Do not create a `TestStartEmbedded` that actually starts an embedded instance -- that would be a heavyweight integration test. The compile gate covers StartEmbedded's existence, and `internal/runtime/embedded_test.go` has deep behavioral tests. Instead, the DefaultEmbeddedConfig test (Test 6) covers the embedded facade path.
