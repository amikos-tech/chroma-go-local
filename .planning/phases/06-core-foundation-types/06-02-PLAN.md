        Note on quoting: SnakeYAML's DOUBLE_QUOTED scalar style will quote ALL scalars including integers and booleans. To match Go output (integers/booleans unquoted, strings quoted), use a custom `Representer` that only quotes String values, or build the YAML manually via LinkedHashMap and let SnakeYAML handle it with its default Representer but override scalar representation. The key requirement is that the YAML, when parsed back by the Rust shim's serde_yaml, produces the same values.

        Recommendation: Use SnakeYAML default settings (BLOCK flow, no forced scalar style) and in golden tests, parse the output YAML back into a Map and compare key-value pairs semantically rather than string equality. This avoids brittleness from quoting differences while ensuring correctness.
