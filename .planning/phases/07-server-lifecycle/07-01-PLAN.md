**Retrofit serverStop():**
Replace inline try-catch with `callFfiVoid`. Note: `chroma_server_stop` returns int (0=success). Check return code and throw via callFfiVoid pattern:
```java
private void serverStop(long handle) {
    if (handle == 0L) return;
    callFfiVoid(() -> {
        int rc = bindings.chroma_server_stop(new Pointer(handle));
        if (rc != 0) {
            throw new ChromaException("server stop failed (rc=" + rc + ")");
        }
    });
}
```
Note: `callFfiVoid` acquires the lock, runs the Runnable, then checks `readLastError()`. If the Runnable throws, callFfiVoid propagates it. If `readLastError()` returns non-null after success, it throws. The rc check inside the Runnable is an additional guard.

**Retrofit serverFree():**

Note: serverFree is called in finally blocks and should not throw. It does NOT go through callFfiVoid because free operations should not check lastError (the Rust side does not set error on free). Keep it minimal.

**Retrofit serverPort():**
Port returns int directly, not a string pointer. Use callFfiHandle pattern but adapted -- since port is not a pointer, handle it directly within FFI lock scope:
```java
private int serverPort(long handle) {
    int port = (int) callFfiHandle(() -> {
        int p = bindings.chroma_server_port(new Pointer(handle));
        if (p < 0) {
            return 0L;  // triggers callFfiHandle's null-check -> reads lastError
        }
        return (long) p;
    });
    return port;
}
```
Wait -- this is awkward because callFfiHandle expects a long and treats 0L as error. Port is int. Better approach: acquire the lock manually for this one case, or just keep it simple with the lock:
```java
private int serverPort(long handle) {
    return (int) callFfiHandle(() -> {
        int p = bindings.chroma_server_port(new Pointer(handle));
        if (p < 0) return 0L;
        return (long) p;
    });
}
```
This works because: negative port -> returns 0L -> callFfiHandle sees 0L -> reads lastError -> throws. Non-negative port -> cast to long -> returned. The final cast back to int recovers the original value. Port 0 itself would be treated as error, but port 0 is not a valid return from a started server.
