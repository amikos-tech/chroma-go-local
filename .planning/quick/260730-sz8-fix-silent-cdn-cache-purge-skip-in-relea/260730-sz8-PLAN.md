<objective>
Make the CDN cache-purge skip loud instead of silent in `.github/workflows/release.yml` (GitHub issue #97).

Today the step is gated with `if: vars.CF_ZONE_ID != ''`. Neither `CF_ZONE_ID` (repo variable) nor `CLOUDFLARE_API_TOKEN` (repo secret) is currently set on this repo, so on every release the step is marked "skipped" by GitHub Actions with **no annotation at all**. The release run is fully green while `releases.json` and `latest.json` stay stale at the Cloudflare edge for up to 24h.

Purpose: a maintainer reading a green release run must be able to see that CDN purging did not happen, and which credential is missing.
Output: one modified step in `.github/workflows/release.yml`. No other file changes.

**Explicitly out of scope** (do not attempt): setting the real `CF_ZONE_ID` / `CLOUDFLARE_API_TOKEN` values (requires Cloudflare credentials we do not have), and changing the Cloudflare cache-rule / TTL configuration (lives in the Cloudflare dashboard, outside this repo).
</objective>

      - name: Purge release metadata from CDN cache
        if: vars.CF_ZONE_ID != ''
        shell: bash
        env:
          CF_ZONE_ID: ${{ vars.CF_ZONE_ID }}
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          PROJECT: chroma-go-local
          RELEASES_DOMAIN: ${{ vars.RELEASES_DOMAIN || 'releases.amikos.tech' }}
        run: |
          set -euo pipefail
          if [ -z "${CLOUDFLARE_API_TOKEN}" ]; then
            echo "CLOUDFLARE_API_TOKEN is not set; skipping cache purge."
            exit 0
          fi
          curl -sf -X POST \
            "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/purge_cache" \
            -H "Authorization: Bearer ${CLOUDFLARE_API_TOKEN}" \
            -H "Content-Type: application/json" \
            --data "{\"files\":[\"https://${RELEASES_DOMAIN}/${PROJECT}/latest.json\",\"https://${RELEASES_DOMAIN}/${PROJECT}/releases.json\"]}"

  <action>
Edit only the `Purge release metadata from CDN cache` step in the `publish-release` job (currently lines 461-479). Make exactly two changes; leave `shell`, the whole `env:` block, the step name, and the step's position in the job untouched.

Change 1 — delete the entire `if: vars.CF_ZONE_ID != ''` line so the step is unconditional and can never be reported as "skipped".

Change 2 — replace the existing token-only guard (the `if [ -z "${CLOUDFLARE_API_TOKEN}" ]` block that echoes a plain message and exits 0) with a guard that checks *both* credentials and reports via a GitHub Actions annotation. Keep `set -euo pipefail` as the first line and keep the `curl` invocation byte-for-byte identical.

The guard logic, which has been dry-run verified against all four credential combinations:
1. Initialise an accumulator variable `MISSING` to the empty string.
2. If `CF_ZONE_ID` is empty, set `MISSING` to the text `CF_ZONE_ID (repository variable)`.
3. If `CLOUDFLARE_API_TOKEN` is empty, append `CLOUDFLARE_API_TOKEN (repository secret)` to `MISSING`, comma-separated when `MISSING` is already non-empty, otherwise assign it directly.
4. If `MISSING` is non-empty, echo a single-line annotation using the `::warning title=CDN cache not purged::` prefix. The message body must interpolate `${MISSING}`, must state that the CDN cache was NOT purged, and must name the two affected URLs built from `${RELEASES_DOMAIN}` and `${PROJECT}` (`latest.json` and `releases.json`) as potentially stale at the edge until the CDN TTL expires. Then `exit 0` — this stays non-fatal, matching the step's existing philosophy; the release must still publish.
5. Otherwise fall through to the unchanged `curl` purge call.

Hard requirements while writing the guard:
- Use full `if ... then ... fi` blocks. Do NOT use the `[ -z "${VAR}" ] && MISSING=...` one-liner form: under `set -e` a false test makes the compound command return non-zero and aborts the step, which would turn a missing credential into a failed release — the exact opposite of the requirement.
- The annotation must be a single physical line. GitHub truncates annotations at the first newline; multi-line requires `%0A` escaping, which is not needed here.
- Never interpolate `${CLOUDFLARE_API_TOKEN}` (or any secret value) into the annotation text — name the variable only. GitHub's secret masking is a backstop, not a licence to echo secrets.
- Preserve the surrounding two-space YAML indentation and the `run: |` block scalar indentation so the diff stays confined to this step.
