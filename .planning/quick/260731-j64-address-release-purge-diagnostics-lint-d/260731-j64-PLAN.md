## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> Cloudflare API | Zone identifier, bearer token, purge payload, HTTP status, and response body cross an external-service boundary |
| Cloudflare response -> public Actions log | Untrusted remote body content becomes maintainer-visible diagnostic text |
| Purge step -> GitHub release publication | Purge exit status can suppress or permit the following publication step |
| CI/local hosts -> Go module source | The lint path resolves the pinned actionlint module and executes it against repository workflows |
| Repository paths -> yamllint | Git-ignore patterns decide which local YAML files enter the lint boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-j64-01 | Information Disclosure | purge request and diagnostics | mitigate | Never print `CLOUDFLARE_API_TOKEN`; helper annotations contain fixed text; harness fails on a token sentinel |
| T-j64-02 | Spoofing / Tampering | remote body in Actions log | mitigate | Prefix body as ordinary log text, cap it at 512 bytes, and retain `tr '\r\n' '  '` so remote newlines cannot create workflow commands |
| T-j64-03 | Denial of Service | purge-to-publication handoff | mitigate | Every expected failure warns then exits 0, `continue-on-error` covers unexpected step failure, final run command is explicit `exit 0`, and the harness asserts publication reachability |
| T-j64-04 | Tampering | Cloudflare success response | mitigate | Require 2xx plus exact boolean success:true; expose status/body on rejection; match the supplied code-1012 token-scope failure by both code and message so it receives Cache Purge permission remediation rather than an unrelated payload diagnosis |
| T-j64-05 | Repudiation | runner/tooling failures | mitigate | Guard jq, ShellCheck, and yamllint explicitly and identify missing local tooling instead of blaming Cloudflare or hiding a skipped lint class |
| T-j64-06 | Tampering | lint toolchain drift | mitigate | Pin actionlint from one version file; use one Make target in CI and locally; log ShellCheck/yamllint versions without brittle exact equality |
| T-j64-SC | Tampering | npm/pip/cargo package installs | accept | No new npm, pip, or cargo package installation is introduced; the already-selected actionlint Go module stays pinned at v1.7.11 and Go checksum verification remains in effect |
</threat_model>
